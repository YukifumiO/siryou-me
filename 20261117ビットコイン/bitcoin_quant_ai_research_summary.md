# Bitcoin定量分析・AI自動売買 研究開発計画書

## 1. 文書の目的

本文書は、`bitcoin_quant_research_project_instructions.md`に記載されたBitcoin定量分析・自動売買プロジェクトの方針と、機械学習、ディープラーニング、AIを用いた市場パターン検出方法に関する調査結果を統合した実行計画書である。

本プロジェクトは、Bitcoin価格の上昇・下落を感覚的に予想することを目的としない。市場仮説をデータとコードによって検証し、成立しない仮説を否定できる、再現可能な研究基盤を構築することを目的とする。

---

## 2. プロジェクトの位置づけ

本プロジェクトは、初期段階では「投資事業」ではなく「研究開発プロジェクト」と位置づける。

利益の獲得だけでなく、次の技術を社内資産として蓄積する。

- 外部API連携
- 時系列データ収集・保存
- データ品質管理
- 統計分析・可視化
- 機械学習・ディープラーニング
- リアルタイム判定
- リスク管理
- 注文・約定管理
- 自動監視・障害検知
- 実験の再現性と監査可能性

したがって、「Bitcoinで利益が出なければ失敗」とは評価しない。仮説を適切に否定した結果も、意思決定に役立つ研究成果とする。

## 3. 基本原則

### 3.1 仮説検証の順序

開発と運用は必ず次の順序で進める。

```text
市場仮説を定義する
↓
必要なデータを収集する
↓
データ品質を検査する
↓

↓

↓

```

- 「上がりそう」といった裁量による発注

- ナンピン、倍賭け、マーチンゲール
- 初期段階でのレバレッジ、先物、オプションの実運用
- APIキーや秘密情報のソースコードへの直接記載
- 未来データを使用したバックテスト
- 手数料、スプレッド、スリッページを無視した性能評価
- 実験の都度、テストデータの結果を見てモデルを調整すること

## 7. 分析対象と仮説

### 7.1 初期仮説

#### 仮説A：ドル価値低下とリスク資産への流入

```text
DXY下落
＋ Gold上昇
＋ BTC ETF純流入
＋ BTCが長期移動平均線より上
```

上記条件の24時間後、72時間後、7日後のBTCリターンを検証する。

#### 仮説B：非ドル資産への資金分散

```text
米10年債利回り上昇
＋ DXY下落
＋ Gold ETF流入
＋ BTC ETF流入
```

この状態が米国資産から非ドル資産への分散と関係するかを検証する。

#### 仮説C：上昇局面のオプション需要

```text
BTC価格上昇
＋ DVOL上昇
```

オプション需要の増加または過熱の先行指標になるかを検証する。

#### 仮説D：恐怖と売却圧力

```text
BTC価格下落
＋ DVOL急騰
＋ Exchange Inflow増加
```

その後の急落、リバウンド、ボラティリティとの関係を検証する。

### 7.2 AIに発見させるパターン

AIを価格予想器としてだけ使用せず、以下の構造を発見させる。

- 上昇・下落・横ばいの市場レジーム
- 高ボラティリティと低ボラティリティの遷移
- 価格、出来高、OI、Fundingの不一致
- ETFフローに対する価格反応の違い
- DXY、Gold、金利からBTCへの先行関係
- DVOLとBTCリターンの非対称な関係
- 流動性悪化や恐怖局面の予兆
- 従来と異なる異常状態

## 8. 予測ターゲットの設計

### 8.1 価格水準ではなくリターンを予測する

価格水準は非定常性が強いため、対数リターンを基本とする。

```text
return_h = log(BTC[t+h] / BTC[t])
```

予測期間は次を候補とする。

- 1時間後
- 6時間後
- 24時間後
- 72時間後
- 7日後

初期実装では、データ収集粒度と売買コストのバランスから、24時間、72時間、7日を優先する。

### 8.2 回帰問題

- 将来リターン
- 将来実現ボラティリティ
- 最大順行幅
- 最大逆行幅
- 将来のドローダウンリスク

### 8.3 3分類問題

単純な上昇・下落の2分類ではなく、以下の3分類を基本とする。

```text
上昇：将来リターン > 往復取引コスト + 安全幅
下落：将来リターン < -(往復取引コスト + 安全幅)
見送り：それ以外
```

これにより、予測値が小さく、取引コストに負ける可能性が高い場面での売買を抑制する。

## 10. 機械学習・AIモデルの採用方針

### 10.1 推奨する3層構成

単一のAIモデルに全てを担当させず、次の3層に役割を分ける。

```text
第1層：教師なし学習で市場状態を発見
↓
第2層：木ベース機械学習で将来リターンを推定
↓
第3層：時系列ディープラーニングと比較
```

### 10.2 ベースライン

AIの有効性を判定するため、必ず単純な比較対象を作成する。

- Buy & Hold
- 常に見送り
- 前期と同じ方向を予測するナイーブモデル
- 移動平均ルール
- 線形回帰
- ロジスティック回帰
- 単純なモメンタム・リバーサル戦略

### 10.3 第一候補：XGBoost / LightGBM

初期の主力モデルとしてXGBoostまたはLightGBMを使用する。

採用理由：

- 金融・マクロ指標のような表形式データを扱いやすい
- 非線形な特徴量の組み合わせを学習できる
- ディープラーニングより少ないデータで比較的安定しやすい
- 学習と推論の計算コストが低い
- SHAPによる予測根拠の解釈がしやすい
- ハイパーパラメータと特徴量の管理が容易

最初に作成するモデル：

| モデル | 出力 |
|---|---|
| Model A | 24時間後の上昇・下落・見送り |
| Model B | 72時間後の上昇・下落・見送り |
| Model C | 7日後の上昇・下落・見送り |
| Model D | 各期間の期待リターン |
| Model E | 将来の実現ボラティリティ |

### 10.4 パターン発見・市場レジーム

教師なし学習で市場状態を抽出する。

| 手法 | 用途 |
|---|---|
| Hidden Markov Model | 時系列的な状態遷移とレジーム確率 |
| Gaussian Mixture Model | 連続量特徴の確率的クラスタリング |
| Pólya tree | 正規分布では捉えにくい非対称性、厚い裾、複数の山を持つ分布のベイズ非パラメトリック推定 |
| 状態別Pólya tree混合 | 各市場状態に柔軟な分布を持たせ、日ごとの状態所属確率を推定 |
| HMM + Pólya tree観測分布 | 市場状態の持続・切り替わりと、各状態内の非正規な分布を同時に表現 |
| K-means | 解釈しやすい基礎的な市場状態分類 |
| HDBSCAN | クラスタ数が不明なデータとノイズ検出 |
| PCA | 市場を動かす共通因子の要約 |
| UMAP | 多変量市場状態の低次元可視化 |
| Isolation Forest | 異常相場やデータ異常の検出 |
| Autoencoder | 複雑な正常状態からの逸脱検出 |

想定するレジームの例：

```text
Regime 1：低ボラティリティ・上昇
Regime 2：高ボラティリティ・上昇
Regime 3：高ボラティリティ・下落
Regime 4：低ボラティリティ・横ばい
Regime 5：資金流入・価格停滞
Regime 6：恐怖急拡大・流動性悪化
```

各レジームについて、将来リターン、ボラティリティ、ドローダウン、継続期間、遷移先を計測する。

#### Pólya treeの位置づけ

Pólya tree（ポリア木）は、観測空間を再帰的に分割し、各分岐で左右の領域へ配分する確率を学習するベイズ非パラメトリックモデルである。基本形では、各分岐の確率にベータ事前分布を置き、各領域に入った観測数によって事後分布を更新する。

ただし、Pólya treeを1本だけ市場データ全体に当てはめた場合、得られるのは原則として「市場データ全体の柔軟な分布」であり、GMMのような状態所属確率ではない。そのため、目的に応じて次の3つの使い方を区別する。

1. **単一のPólya tree**  
   リターンとボラティリティの同時分布、裾確率、条件付き損失確率の推定に使う。例えば「高ボラティリティ時にBTCリターンが-3%を下回る確率」の推定に適する。
2. **状態別Pólya treeを持つ混合モデル**  
   「平穏70%、ストレス30%」のような状態所属確率を出力する。各1状態を1つの正規分布で表すGMMより、状態内の歪度、厚い裾、複数の山を表現しやすい。
3. **HMMの観測分布にPólya treeを使うモデル**  
   市場状態の持続確率と遷移確率をHMMで扱い、各状態から発生する観測値の分布をPólya treeで表現する。「状態の持続・切り替わり」と「状態内の非正規性」の両方が重要な場合の候補とする。

#### GMMとPólya treeの比較

| 比較点 | GMM | 状態別Pólya tree混合 |
|---|---|---|
| 1つの状態の表現 | 平均と共分散を持つ正規分布 | 分割領域ごとの確率配分 |
| 各観測の出力 | 各ガウス成分への所属確率 | 各状態への所属確率 |
| 非対称性・厚い裾 | 複数成分の重ね合わせで近似 | 1状態の分布内で直接表現可能 |
| 複数の山 | 複数ガウス成分が必要で、同一状態への再統合が必要になる場合がある | 同一状態内の形状として表現可能 |
| 少数データ領域 | 平均・共分散が強い形状制約となる | 分割位置、深さ、事前分布の影響が大きい |
| 多変量への拡張 | 共分散で依存関係を簡潔に表現 | 変数と分割の順序に敏感で、次元増加で各領域のデータが希薄化 |
| 実装・計算 | 標準的な実装が多く高速 | モデル設計と推論が複雑で、検証コストが高い |

#### 採用判断

Pólya treeはGMMを最初から置き換えるのではなく、GMMを比較基準とした上で追加実験する。次の条件が繰り返し観測される場合に導入価値が高い。

- GMMの各状態内に強い歪度や厚い裾が残る
- 1つの解釈可能な市場状態が、複数のガウス成分に分裂される
- GMMの密度予測や裾確率がホールドアウトで較正不良となる
- リターンの左裾や、ボラティリティ条件付き損失確率が重要な研究対象になる

一方、多変量のPólya treeは分割方法と事前分布に敏感であり、特徴量が増えると各領域の観測数が急減する。そのため、初期実験ではリターン、実現ボラティリティ、出来高変化、DVOL変化などの2～4変数程度に限定する。

#### Pólya treeの検証項目

- 外部期間に対する密度予測の対数スコア
- CRPSなどの確率予測評価
- 左裾確率と実現頻度の校正
- 状態所属確率の安定性
- 学習期間を変えた場合のレジーム再現性
- 分割位置、木の深さ、事前分布に対する感度
- GMMに対するホールドアウト性能の改善
- モデルが検出した状態の経済的な解釈可能性
- 取引コスト控除後の戦略改善の有無

### 10.5 ディープラーニング

ディープラーニングは、データ基盤とXGBoostベースラインが完成した後に導入する。

推奨比較順序：

1. 小型LSTM
2. GRU
3. Temporal Fusion Transformer（TFT）
4. PatchTST
5. iTransformer

#### LSTM / GRU

時系列ニューラルネットの基礎比較用として使用する。大規模化させず、少数層・小さい隠れ次元で過学習を抑制する。

#### Temporal Fusion Transformer

TFTは、多変量と複数予測期間を扱い、特徴量選択と時間方向の重要度を解釈できるため、本プロジェクトの深層学習の第一候補とする。分位点予測を使うことで、点予測だけでなく不確実性を出力できる。

#### PatchTST / iTransformer

長い入力系列や多変量時系列の比較実験に使用する。ただし、一般的な時系列ベンチマークでの高性能は、Bitcoin取引のコスト控除後性能を保証しない。

### 10.6 採用条件

高度なモデルは、次の条件を満たす場合だけ採用する。

- 未知期間で簡単なベースラインを上回る
- コスト控除後の成績が改善する
- 特定の年やレジームだけに依存しない
- 複数の学習シードで結果が大きく変動しない
- 予測の根拠または限界を説明できる
- 運用に必要な計算時間と保守コストが許容範囲内である

## 11. 説明可能性

### 11.1 SHAP

XGBoost / LightGBMにはSHAPを適用し、予測値を特徴量ごとの寄与に分解する。

確認する内容：

- 全体で重要な特徴量
- 個別予測で上昇・下落判定に寄与した要因
- 特徴量の値と寄与の非線形関係
- レジームごとの特徴量重要度の変化
- 学習期間と検証期間の重要度変化

### 11.2 解釈の注意点

- SHAPは因果関係ではなく、学習済みモデル内の寄与を示す
- 相関の強い特徴量間で寄与が分散する可能性がある
- 注意機構の重みだけを因果的な説明とみなさない
- モデルの説明と、戦略が経済的に有効であることは別問題である

## 12. 検証設計

### 12.1 ランダム分割の禁止

金融時系列に通常のランダムな学習・テスト分割やShuffleSplitを使用しない。過去で学習し、その後の未知期間で評価する。

### 12.2 ウォークフォワード検証

```text
Fold 1：[学習] [gap] [検証]
Fold 2：[   学習期間を前進   ] [gap] [検証]
Fold 3：[       学習期間を前進       ] [gap] [検証]
```

学習窓は次の両方を比較する。

- Expanding window：古いデータを累積する
- Rolling window：一定期間より古いデータを除外する

Bitcoin市場は構造変化が大きいため、ローリング窓の方が有利な場合がある。どちらを採用するかはテスト結果で判定する。

### 12.3 GapとPurging

予測ラベルに将来期間のリターンを使うため、学習と検証の境界でラベル期間が重複しないようにする。

例：

- 24時間後予測：原則24時間相当のgap
- 72時間後予測：原則72時間相当のgap
- 7日後予測：原則7日相当のgap

保有期間が重複する事例を扱う場合は、purgingやembargoを導入する。

### 12.4 ネステッド評価

ハイパーパラメータ選択に使用する検証期間と、最終性能を評価するテスト期間を分離する。

```text
内側検証：特徴量・パラメータ選択
外側検証：選択済みパイプラインの性能評価
最終ホールドアウト：開発中に繰り返し見ない
```

### 12.5 前処理のリーク防止

次の処理は各学習フォールド内でfitし、検証データへtransformする。

- 標準化・正規化
- 欠損補完
- 外れ値処理
- PCA
- 特徴量選択
- クラス重みの決定
- 分類閾値の選択

全期間で前処理をfitしてから分割する方法は禁止する。

## 14. バックテストの必須条件

### 14.1 取引コスト

最低限、次を含める。

- Maker / Taker手数料
- Bid-Askスプレッド
- スリッページ
- 部分約定
- 注文キャンセル失敗
- API遅延
- 必要に応じて税務と資金移動コスト

### 14.2 シグナルから約定までの時刻

例えば、時間足の終値で特徴量を計算した場合、同じ時間足の始値で約定したことにはできない。特徴量計算、シグナル生成、送信遅延の後に約定可能な価格を使う。

### 14.3 取引閾値

機械学習が出す全予測で売買しない。

```text
予測期待リターン
> 手数料 + スプレッド + 予想スリッページ + 安全幅
```

を満たす場合だけシグナル候補とする。この閾値もテスデータを見て調整しない。

## 15. リスク管理

### 15.1 資産の分離

長期保有用Bitcoinと研究用売買資金を分離する。

```text
長期保有部分
→ 自動売買システムの対象外

研究・自動売買部分
→ 事前に決定した実験資金の範囲内で使用
```

### 15.2 停止条件

利益目標より先に損失上限を決定する。

例：

```text
研究資金：20万円
最大許容ドローダウン：20%
累積損失4万円で自動停止
```

実際の金額と比率は別途決定するが、停止条件はコードで強制し、人間の判断で解除しない。

### 15.3 その他の安全装置

- 初期は現物のみ
- 1回あたりの最大注文金額
- 1日あたりの最大損失
- 連続損失回数による停止
- 異常なスプレッドでの発注停止
- 古いデータを使用した発注の防止
- API、DB、時刻同期の異常時の発注停止
- 二重発注を防ぐ冪等性キー
- 注文状態不明時に追加発注しない
- 手動の緊急停止機能

## 22. 現時点の推奨結論

本プロジェクトにおける初期の最適構成は次のとおりである。

```text
市場データ収集・品質管理
↓
HMM / GMM / クラスタリングで市場レジームを発見
↓
GMMが状態内の非対称性・厚い裾を捉えられない場合は
Pólya tree混合またはHMM + Pólya treeを比較
↓
XGBoost / LightGBMで将来リターンと確率を推定
↓
SHAPで予測根拠を分析
↓
取引コストを超える場合だけシグナル候補とする
↓
Gap / Purging付きウォークフォワードで検証
↓
TFTなどの深層学習を比較モデルとして追加
```

最も重要な考え方は、次のとおりである。

> AIに上昇・下落の判断を丸投げするのではなく、AIに市場パターンを発見させ、そのパターンが未知期間でも、取引コスト控除後に有効かを検証する。
