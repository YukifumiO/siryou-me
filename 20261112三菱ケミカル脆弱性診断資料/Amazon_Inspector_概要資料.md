# Amazon Inspector 概要資料

- 作成日：2026年11月12日
- 対象：Amazon Inspectorの基本機能およびEC2のSSMエージェント方式
- 本資料はサービスの仕組み・機能・診断範囲を説明する技術資料であり、個別環境の診断結果を示すものではない。

## 1. Amazon Inspectorとは

Amazon Inspectorは、AWSが提供する**継続的な脆弱性管理サービス**である。対象リソースを検出し、ソフトウェアに存在する既知の脆弱性や、意図しないネットワークへの露出を評価する。

脆弱性が見つかった場合は、対象リソース、脆弱性識別子（CVE）、重要度、影響するパッケージ、修正に関する情報などを「検出結果（Finding）」として表示する。

**特徴**

- 対象となるリソースを自動的に検出する。
- 一度限りではなく、脆弱性情報や環境の変化に合わせて継続的に評価する。
- リスクに基づいて対応の優先順位を判断できる。
- 検出結果をCSVまたはJSONでエクスポートできる。
- Amazon EventBridgeやAWS Security Hub CSPMなどと連携できる。

## 2. 主な診断対象

| 対象 | 主な診断内容 |
| --- | --- |
| Amazon EC2 | OS・ソフトウェアパッケージの既知の脆弱性、ネットワーク到達可能性 |
| Amazon ECR | コンテナイメージに含まれるOS・言語パッケージの脆弱性 |
| AWS Lambda | 対応する依存パッケージの脆弱性。オプションでコードスキャンも可能 |
| その他の対応リソース | AMIやコードリポジトリなど、別途有効化・利用条件のあるスキャン機能 |

対象の種類や利用できる機能はリージョン・設定・サービスの更新により異なる。以降は**EC2のSSMエージェント方式**を中心に説明する。

## 3. EC2で調査する内容

### 3.1 OS・ソフトウェアパッケージの脆弱性

EC2から収集したソフトウェア情報と、既知の脆弱性情報・ベンダーのセキュリティアドバイザリなどを照合する。

対象の例：

- Linuxなどの対応OSのパッケージ
- OpenSSLなどのシステムライブラリ
- Apache HTTP Server、Nginxなどの対応するインストール済みパッケージ
- 対応するアプリケーション言語の依存パッケージ（詳細検査の対象となる場合）

**注意：** インストール形態やOS、パッケージ管理方式、詳細検査の設定などによって、検出できるソフトウェアは異なる。製品名が上記にあるからといって、任意のインストール方法・バージョンが必ず診断されるわけではない。

### 3.2 ネットワーク到達可能性

AWSのネットワーク設定をもとに、EC2への到達経路や意図しない公開状態を評価する。

分析に利用する設定の例：

- Security Group
- Network ACL
- Route Table
- Internet Gateway
- VPC / Subnet
- Load Balancerなどのネットワーク関連リソース

ネットワーク到達可能性の評価は、一般的な外部侵入テストや実機への全面的なポートスキャンと同一ではない。

## 4. EC2スキャンの方式

| 方式 | ソフトウェア情報の取得方法 | 特徴 |
| --- | --- | --- |
| エージェントベース（標準） | SSM Agent、SSM関連付け、Inspector SSMプラグイン | SSM管理対象EC2から情報を収集して継続評価 |
| エージェントベース（拡張） | SSMを用いてInspector VM Scannerを導入（自動導入の場合） | より統一的なパッケージ収集・評価方式 |
| エージェントレス | EBSスナップショットを使用 | 対応条件を満たす、SSMで管理されていないEC2も評価可能 |

SSMエージェント方式では、概ね次の流れで動作する。

```text
EC2インスタンス
  └─ SSM Agent / Inspectorプラグインなど
       ↓ ソフトウェアのインベントリ収集
Amazon Inspector
       ↓ 既知の脆弱性情報と照合
検出結果（Finding）
       ↓
重要度の確認・修正・再評価
```

### 4.1 SSMエージェント方式の主な前提条件

- 対象OSが対応していること。
- EC2が同じAWSアカウントのSystems Managerの管理対象になっていること。
- SSM Agentが動作し、必要なIAM権限と通信経路があること。
- Inspectorの対象スキャンが有効であり、除外設定の対象ではないこと。

**SSM Agentが動作していることだけでは、Inspectorの正常なスキャン完了は保証されない。** カバレッジ画面で監視状態を確認する必要がある。

## 5. 診断・評価の間隔

Amazon Inspectorは、すべての診断を一定間隔で一斉に実行する仕組みではない。取得するデータやスキャン方式で周期が異なる。

| 項目 | 標準的な周期・タイミング | 補足 |
| --- | --- | --- |
| 標準SSM方式のインベントリ評価 | **既定で30分ごと** | 「最終スキャン日時」もこの評価などにより更新される。毎回全面的な攻撃テストを行う意味ではない |
| 新規EC2の起動 | 対象になった際にスキャン | スキャン条件を満たす場合 |
| Linux/Macでのソフトウェア変更 | 変更に応じて再評価 | 変更検出・情報収集の状況に依存 |
| 関連する新しいCVEの追加 | 情報追加に応じて再評価 | 対象インスタンスに該当する場合 |
| 標準方式のLinux詳細検査 | **既定で6時間ごとにアプリケーションインベントリ収集** | 詳細検査が適用される場合。周期変更可能 |
| 拡張EC2スキャン（Inspector VM Scanner） | **既定で3時間ごと** | 標準方式とは別の実装 |
| ネットワーク到達可能性 | **12時間ごと** | AWSネットワーク設定に基づく評価 |
| エージェントレススキャン | **24時間ごと** | ハイブリッドモードで対象となるインスタンスの場合 |

※ 各周期はAWS公式資料に示された標準動作であり、個々のリソースの処理完了時刻や結果更新時刻を保証するものではない。

## 6. 脆弱性の重要度と検出結果

Amazon Inspectorは、検出結果に重要度を付ける。主な分類は以下のとおり。

| 重要度 | 意味 |
| --- | --- |
| Critical（緊急） | 最優先で確認する必要がある重大な問題 |
| High（高） | 優先度の高い問題 |
| Medium（中） | 影響と悪用条件を評価して対応する問題 |
| Low（低） | 相対的に優先度の低い問題 |
| Informational（情報） | 情報提供として扱うもの |

重要度は脆弱性の種類により評価方法が異なる。ソフトウェアパッケージの検出結果ではCVSSなどの情報を使用し、EC2では環境に応じたInspectorスコアが利用できる場合がある。

検出結果には、通常、以下のような情報が含まれる。

- 対象のEC2インスタンスIDやリソース情報
- CVE番号または検出結果の種類
- 影響するパッケージおよびバージョン
- 重要度・スコア
- 最初に確認された日時、最後に確認された日時
- 修正可能性、修正バージョンまたは推奨対処

検出結果がないことは、**対象スキャンの検査範囲内で問題が検出されなかった**ことを意味し、システム全体に脆弱性が存在しないことの保証ではない。

## 7. 検査できない内容・限界

Amazon InspectorのEC2スキャンは、Webアプリケーションへの総合的な攻撃テストを代替するものではない。

| 項目 | EC2スキャンの扱い |
| --- | --- |
| 対応OSパッケージの既知のCVE | 検出対象 |
| 対応する言語依存パッケージの既知のCVE | 詳細検査等の対応条件によって検出対象 |
| AWSネットワークの到達可能性 | 検出対象 |
| 独自開発のアプリケーションロジック | EC2パッケージスキャンでは原則対象外 |
| SQLインジェクション | EC2パッケージスキャンでは対象外 |
| クロスサイトスクリプティング（XSS） | EC2パッケージスキャンでは対象外 |
| ログイン・権限設計の不備 | EC2パッケージスキャンでは対象外 |
| CMS固有の未知の脆弱性 | EC2パッケージスキャンでは原則対象外 |
| CISベンチマーク準拠 | 別機能としてのCISスキャン等で評価。通常のCVEスキャンとは異なる |

特に、PowerCMSのようなCMS自体のアプリケーション脆弱性は、OSの既知のパッケージ脆弱性とは別に考える必要がある。

## 8. 画面で確認できる情報とエクスポート

Amazon Inspectorコンソールでは、概ね以下を確認できる。

1. **ダッシュボード：** 検出結果や重要度、対象リソースの状況
2. **検出結果（Findings）：** CVE・影響範囲・修正情報の詳細
3. **カバレッジ・インスタンス一覧：** 監視対象かどうか、最終スキャン日時、スキャン方式など
4. **スキャン設定：** EC2スキャンの方式、詳細検査等の設定

検出結果のエクスポート形式は**CSV**または**JSON**である。CSV/JSONの出力には、必要なS3バケットやKMSキー、権限などの設定が関係する。Inspectorから直接PDF形式の診断レポートが標準出力されるとは限らない。

## 9. 料金の考え方

Amazon Inspectorは利用量に応じた従量課金サービスである。

- EC2では、月内に評価されたインスタンスの平均台数などを基に課金される。
- 月の一部だけ稼働したインスタンスは、稼働時間に応じて按分される。
- ECR、Lambda、AMIなどは、それぞれ別の料金体系がある。
- 追加の診断機能や周辺AWSサービスの利用により、別途費用が生じる場合がある。
- 料金はリージョンやAWSの価格改定により変わるため、利用前に公式料金表で確認する。

公式料金表：<https://aws.amazon.com/inspector/pricing/>

## 10. 利用上の注意事項

- **対象範囲の確認：** スキャンを有効化しただけで、すべてのEC2が監視対象になるとは限らない。
- **対応OSの確認：** OSの種類・バージョンによりサポート可否が異なる。
- **詳細検査の確認：** アプリケーション言語や収集対象のディレクトリによって検出範囲が異なる。
- **継続監視：** 新しいCVEやソフトウェア更新に応じて結果が変わる。
- **修正対応：** 脆弱性の検出と修正は別作業であり、基本的に管理者による対応が必要である。
- **補完的な検査：** アプリケーション診断、設定監査、侵入テスト等とは目的・範囲が異なる。

## 11. 用語集

| 用語 | 意味 |
| --- | --- |
| CVE | 公開された脆弱性を識別するための共通ID |
| CVSS | 脆弱性の深刻度を数値化する共通の評価方式 |
| Finding | Inspectorが検出した脆弱性やネットワーク到達性に関する結果 |
| SSM Agent | AWS Systems Managerの管理操作などをEC2上で実行するエージェント |
| インベントリ | インストール済みパッケージやソフトウェアの情報 |
| 詳細検査（Deep inspection） | OS以外の対応するアプリケーション言語パッケージも調べる機能 |
| Inspector VM Scanner | 拡張EC2スキャンに使われるスキャナー |
| カバレッジ | Inspectorの監視・スキャン対象になっているリソースの範囲・状態 |
