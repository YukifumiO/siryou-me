# Phase 8：少額実売買

## 目的

研究資金のごく一部だけを使用し、実際の取引所API、注文、部分約定、手数料、スリッページを検証する。利益の拡大ではなく、実運用の差分とリスク制御の確認を目的とする。

## 開始前の必須条件

- Phase 7の完了条件を満たしている
- 長期保有資産と研究口座・資金が分離されている
- 実運用額、1回の注文上限、1日の損失上限が承認されている
- 累積損失とドローダウンの自動停止が実装済み
- 取引専用APIキーが最小権限・IP制限付き
- 出金権限のないAPIキーを使用
- 手動緊急停止と連絡網が確立済み

## 作業

### 1. 初期資金とポジション

- 初期は現物のみ
- 研究資金の全額を使わない
- 例として研究資金20万円の場合、2～5万円程度から開始
- 初期はポジション数と注文頻度を制限

### 2. 発注安全性

- 冪等性キーによる二重発注防止
- 発注前の口座残高・既存注文・ポジション確認
- 発注後の取引所照会
- タイムアウト時に盲目的に再発注しない
- 部分約定とキャンセル後残量の管理

### 3. 自動停止

- 1日の最大損失
- 累積損失上限
- 最大ドローダウン
- 連続損失回数
- 異常スプレッド
- 古いデータ・欠損データ
- API障害や注文状態不明
- モデル・入力データのドリフト警告

停止条件は人間の「戻るかもしれない」という判断で解除しない。

### 4. 実績評価

- 理論約定価格と実約定価格の差
- 予想・実際の手数料
- スリッページ分布
- 部分約定率
- キャンセル成功率と遅延
- 予測と実現値の校正
- ペーパートレードと実売買の差

## 成果物

- 承認済み運用条件書
- 自動停止テスト結果
- 注文・約定・残高照合ログ
- 予想コストと実際コストの差分レポート
- 日次・週次リスクレポート
- 障害・インシデント記録

## 完了条件

- [ ] 予定した少額の範囲内で運用している
- [ ] 実注文と実約定を漏れなく照合できる
- [ ] 手数料・スリッページを実測できる
- [ ] 停止条件がコードと運用両方で機能する
- [ ] 実売買とペーパー取引の差を説明できる
- [ ] 資金増額の判定に利益額だけを使っていない

## 注意点

- このPhaseは必ず事前承認を得て開始する。
- レバレッジ、ナンピン、倍賭けは実施しない。
- 一時的な好成績を根拠に運用額を急増させない。
