# Phase 2：データ取得PoC

## 目的

Phase 1で選定したAPIから実際にデータを取得し、認証、応答形式、時刻、値、制限を検証する。この段階では自動売買を実装しない。

## 作業

### 1. 共通取得インターフェース

ソースごとの違いを吸収し、次の入力と出力を揃える。

```text
入力：symbol, start, end, interval
出力：timestamp, source, symbol, OHLCV/value, retrieved_at, available_at
```

### 2. 生データの保存

- APIの生レスポンスを保存する
- 取得時刻、リクエスト条件、HTTPステータスを記録する
- ソース側の仕様変更時に再解釈できる形で保存する

### 3. 標準スキーマへの変換

```text
timestamp
source
symbol
open
high
low
close
volume
value
retrieved_at
available_at
revision
quality_flag
```

価格系、利回り、指数、フローでスキーマを分ける場合も、時刻とソースの意味は統一する。

### 4. エラー確認

- 認証失敗
- レート制限
- タイムアウト
- 空応答
- 不正なJSONやCSV
- 同じタイムスタンプの重複
- 過去期間の上限超過
- 不正な数値・単位

### 5. 秘密情報管理

- APIキーは環境変数またはSecret Managerから読む
- `.env`をバージョン管理の対象外にする
- ログや例外メッセージにキーを表示しない
- 取得専用の最小権限キーを使う

## テスト

- 代表的な1日分の取得
- 複数ページにまたがる取得
- 日付境界を跨ぐ取得
- 同じ条件での再取得
- 過去期間の部分取得
- 一時的なAPI失敗の再現
- 異なるソースとの概略値比較

## 成果物

- ソース別Pythonコネクタ
- 共通取得インターフェース
- 生レスポンスの保存サンプル
- 標準スキーマのサンプルCSVまたはDB
- `data_dictionary.md`
- `poc_results.md`
- 取得コマンドと環境変数の説明

## 完了条件

- [ ] 生データと標準化後データを対応づけられる
- [ ] 再実行で不正な重複を作らない
- [ ] APIキーがコード・ログ・リポジトリに残っていない
- [ ] 制限・失敗時の挙動が記録されている
