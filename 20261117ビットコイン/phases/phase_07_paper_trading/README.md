# Phase 7：ペーパートレード

## 目的

実資金を使わず、リアルタイムデータ、特徴量、モデル推論、注文シミュレーションを統合し、バックテストと実時間挙動の差を測定する。

## 作業

### 1. リアルタイムパイプライン

```text
データ取得
→ 品質・鮮度チェック
→ 特徴量作成
→ レジーム推定
→ 予測
→ リスクチェック
→ 仮想注文
→ 仮想約定
```

### 2. 仮想約定モデル

- シグナル後の注文送信遅延
- 板のBid / Ask
- 注文サイズに応じたスリッページ
- 部分約定
- キャンセル遅延と失敗
- 取引所手数料

### 3. 必須ログ

- 取得データのタイムスタンプ
- 特徴量値
- モデル・特徴量バージョン
- 予測値、予測確率、不確実性
- 市場レジームと確率
- シグナルの採用・却下理由
- 仮想注文価格と仮想約定価格
- コスト内訳
- エラーと再試行

### 4. バックテストとの差分

- データ利用可能時刻の差
- 特徴量計算時間
- 推論時間
- シグナル遅延
- スプレッドとスリッページ
- データ改定
- 注文キャンセルの影響

### 5. 異常系テスト

- API停止
- WebSocket切断
- 古いデータ
- データ欠損
- DB接続失敗
- モデル推論失敗
- 異常スプレッド
- 時刻同期異常

異常時はフェイルクローズとし、仮想であっても注文候補を出さない。

## 成果物

- リアルタイム推論サービス
- 仮想注文・約定エンジン
- 取引ログ・エラーログ
- バックテスト差分レポート
- 異常系テスト結果
- 日次・週次ペーパートレードレポート

## 完了条件

- [ ] 実資金を使わず一連のフローが稼働する
- [ ] シグナルごとの判定根拠を後から再現できる
- [ ] 仮想約定に実際のスプレッドと遅延が反映される
- [ ] 異常時に発注候補が停止する
- [ ] バックテストとの差を数値と理由で説明できる
- [ ] Phase 8に進むか否かの承認資料がある

## 注意点

- ペーパー取引の利益を実売買でも得られると仮定しない。
- ペーパー期間中に戦略を裁量変更しない。変更案は別バージョンとして再バックテストする。
