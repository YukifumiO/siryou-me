# Phase 3：自動データ収集基盤

## 目的

PoCを定期実行可能なデータ基盤へ発展させ、欠損、重複、遅延、改定、障害を検出できる状態にする。

## 作業

### 1. スケジュール設計

- ソースごとの更新頻度と公表遅延に合わせる
- ジョブの開始時刻、タイムアウト、再試行上限を定義する
- 同じジョブの二重起動を防ぐ
- UTCで実行・保存し、表示でJSTへ変換する

### 2. 差分取得とバックフィル

- 最終正常取得時刻から差分を取得する
- 指定期間を再取得できる
- 欠損範囲だけをバックフィルできる
- 改定値を上書きせず履歴管理できる

### 3. 品質チェック

- 期待時刻に対する欠損
- 主キーの重複
- 時刻の逆行
- `low <= open/close <= high`などOHLC整合性
- 価格、出来高、利回りの異常値
- ソース間の大幅な乖離
- `retrieved_at - available_at`による取得遅延
- データの古さ（freshness）

### 4. 監視とアラート

- ジョブ成功・失敗
- 取得件数
- 最終取得時刻
- 欠損数・重複数
- APIレート制限残量
- 応答時間
- 連続失敗回数

### 5. 運用手順

- 通常の再起動
- ソース側障害時の待機
- 代替ソースへの切替え
- 過去データの再構築
- 不正データの隔離
- API仕様変更時のテスト

## 成果物

- 定期取得ジョブ
- 時系列DBスキーマとマイグレーション
- バックフィルコマンド
- データ品質レポート
- 監視メトリクスとアラート
- `data_operations_runbook.md`
- バックアップ・復旧手順

## 完了条件

- [ ] 人手を介さず毎日データが蓄積する
- [ ] 再実行しても重複や不整合を生まない
- [ ] 欠損を自動検出し、期間指定で再取得できる
- [ ] 取得遅延と古いデータを検出できる
- [ ] 失敗時にアラートが発生する
- [ ] バックアップから復旧テストが成功する

## 注意点

- 欠損を安易に前方補完して正常データとみなさない。
- 過去改定のあるデータは、当時利用可能だった値を残す。
- 自動取得成功とデータ内容の正しさは別に監視する。
